# Запуск платформы на сервере

Пошаговая инструкция: от аренды сервера до работающего сайта, приложения на Android, push-уведомлений
и резервных копий в Telegram. Команды можно копировать как есть, кроме слов ЗАГЛАВНЫМИ буквами —
вместо них подставьте свои данные.

В примерах IP сервера — `1.2.3.4`. Пишите свой.

**Порядок:** 1 → 2 → 3 → 4 обязательно (после этого сайт работает). Дальше — по мере надобности:
приложение (5), push (6), Telegram (7). Разделы 8–11 — для обслуживания.

---

## 1. Сервер

Арендуйте VPS у любого хостинга:

| Параметр | Что выбрать |
|---|---|
| Система | **Ubuntu 24.04** (подойдёт 22.04) |
| Память | от 2 ГБ (лучше 4 ГБ) |
| Диск | от 20 ГБ |
| IP | один публичный IPv4 |

Хостинг пришлёт **IP сервера** и **пароль root** — сохраните их у себя, в чаты не пишите.

**Проверьте в панели хостинга** (раздел Firewall / Security group / Сеть):

- входящие порты **22** (SSH), **80** и **443** (сайт) открыты;
- исходящий интернет не закрыт (серверу нужно скачать программы). Если не уверены — спросите поддержку хостинга:
  «откройте, пожалуйста, исходящие соединения на порты 80, 443 и 53».

## 2. Подключиться к серверу

На компьютере с Windows откройте **PowerShell** (Пуск → набрать «PowerShell») и введите:

```powershell
ssh root@1.2.3.4
```

- На вопрос `Are you sure you want to continue connecting?` напишите `yes` и нажмите Enter.
- Введите пароль root. Символы при вводе не видны — это нормально. Вставить из буфера — правой кнопкой мыши.
- Строка вида `root@имя:~#` значит, что вы на сервере. Выйти — `exit`.

Все команды ниже с `sudo` выполняются **на сервере**, а с пометкой «на компьютере» — в PowerShell на вашем компьютере.

## 3. Установить платформу

На сервере:

```bash
curl -4 -fsSLO https://raw.githubusercontent.com/J0ma2966/b2b-orders/main/deploy/install.sh
sudo bash install.sh
```

Скрипт задаст вопросы:

| Вопрос | Что ответить |
|---|---|
| Домен платформы | Своего домена нет — просто **Enter**. Возьмётся бесплатный адрес вида `1-2-3-4.sslip.io` с настоящим HTTPS. Свой домен можно подключить позже (раздел 10) |
| Почта для Let's Encrypt | Ваша почта (туда придёт письмо, если HTTPS-сертификат не продлится). Можно Enter |
| Телефон супер-админа | Номер, под которым вы будете входить в админку, например `+998901234567` |
| Владелец платформы, почта, телефон | Ваше ИП/ООО и контакты. Они показываются на странице «Политика конфиденциальности» — её требуют Google Play и App Store |

Установка занимает 5–15 минут. Скрипт сам ставит всё нужное: Node.js, базу PostgreSQL, nginx, HTTPS,
службу, ночные резервные копии и firewall; сам создаёт пароль базы и ключи для push в браузере.

В конце появится блок **«Готово»**:

```
  Адрес:        https://1-2-3-4.sslip.io
  Супер-админ:  +998901234567
  Временный пароль супер-админа (показан один раз, при входе попросит сменить):
    Временный пароль: ...
```

**Сохраните адрес и временный пароль** — пароль больше нигде не показывается.

Если установка прервалась (обрыв связи, ошибка) — просто запустите `sudo bash install.sh` ещё раз.
Это безопасно: уже созданные настройки, база и пароли не трогаются.

## 4. Первый вход

1. Откройте в браузере адрес из блока «Готово».
2. Войдите: телефон супер-админа и временный пароль.
3. Платформа попросит придумать новый пароль. Придумайте надёжный и сохраните.

Сайт работает. Поставщики и магазины регистрируются сами по этому адресу, супер-админ одобряет поставщиков в админке.

**Сменить номер супер-админа** (в кабинете номер не меняется, только на сервере):

```bash
sudo b2b-set-admin-phone 90 123 45 67
```

Пароль остаётся прежним, входить дальше по новому номеру. Номер не должен быть занят магазином или поставщиком.

## 5. Приложение для Android (APK)

Приложение собирается бесплатно в GitHub Actions, адрес сервера зашивается в него при сборке.

**Один раз указать адрес сервера:**

1. Откройте репозиторий на GitHub → **Settings → Secrets and variables → Actions** → вкладка **Variables** → **New repository variable**.
2. Name: `MOBILE_SERVER_URL`. Value: адрес сайта из раздела 3, например `https://1-2-3-4.sslip.io` (с `https://`, без `/` в конце). **Add variable**.

**Собрать APK:**

1. GitHub → вкладка **Actions** → слева **Mobile** → справа **Run workflow** → ветка `main` → **Run workflow**.
2. Через 10–15 минут сборка станет зелёной ✓. Откройте её → внизу, в разделе **Artifacts**, скачайте **android-debug-apk**.
3. Это zip-архив, внутри — `app-debug.apk`. Отправьте его на телефон (например, в Telegram «Избранное»).

**Установить на телефон** (Android 8 и новее):

1. Откройте файл → разрешите установку из этого источника → «Установить».
   Play Защита может предупредить о неизвестном разработчике — «Всё равно установить».
2. **Перед установкой новой сборки удалите старое приложение.** Каждая сборка в GitHub подписана своим ключом,
   и Android не даст поставить её поверх старой.

Одно приложение для всех ролей: магазин, поставщик и доставщик видят своё после входа.

**Когда нужен новый APK:** только при смене адреса сервера (раздел 10), подключении Firebase (раздел 6) или
если изменился код в папке `mobile/`. Обычные обновления сайта (раздел 8) появляются в приложении сами.

Для публикации в Google Play и App Store нужна подписанная сборка — см. [mobile.md](mobile.md).

## 6. Push-уведомления

**В браузере** (сайт на компьютере или в Chrome на телефоне) push работают сразу после установки — ключи
создал скрипт. Каждый пользователь включает их у себя: **Мой профиль → «🔔 Включить push на этом устройстве»** и
разрешает уведомления в браузере.

**В приложении Android** push идут через Firebase (бесплатно). Нужно один раз:

**Шаг 1. Создать проект Firebase**

1. Откройте <https://console.firebase.google.com> под своим Google-аккаунтом → **Create a project**
   (название любое, например `b2b-orders`; Google Analytics можно выключить).
2. На странице проекта нажмите значок **Android** → *Android package name*: **`uz.b2borders.app`**
   (ровно так, иначе push не придут) → **Register app**.
3. Скачайте файл **google-services.json**. Остальные шаги мастера пропустите (**Next → Continue to console**).

**Шаг 2. Файл для приложения → в GitHub**

1. Откройте `google-services.json` Блокнотом и скопируйте всё содержимое.
2. GitHub → **Settings → Secrets and variables → Actions** → вкладка **Secrets** → **New repository secret**.
   Name: `GOOGLE_SERVICES_JSON`, Secret: вставьте содержимое → **Add secret**.
3. Пересоберите APK (раздел 5, «Собрать APK»). В журнале сборки, в шаге «Firebase для push», должно быть
   «приложение uz.b2borders.app найдено».

**Шаг 3. Ключ для сервера**

1. Firebase → ⚙ **Project settings → Service accounts → Generate new private key → Generate key**.
   Скачается JSON-файл вида `b2b-orders-firebase-adminsdk-xxxxx.json`. Это секретный ключ: никому не пересылайте.
2. На компьютере, в PowerShell (путь к файлу — свой):
   ```powershell
   scp "$env:USERPROFILE\Downloads\ИМЯ_ФАЙЛА.json" root@1.2.3.4:/opt/b2b-orders/secrets/fcm.json
   ```
3. На сервере:
   ```bash
   sudo chown b2b:b2b /opt/b2b-orders/secrets/fcm.json
   sudo chmod 600 /opt/b2b-orders/secrets/fcm.json
   sudo sed -i 's|^FCM_SERVICE_ACCOUNT_FILE=.*|FCM_SERVICE_ACCOUNT_FILE="/opt/b2b-orders/secrets/fcm.json"|' /opt/b2b-orders/.env
   sudo systemctl restart b2b-orders
   ```

**Шаг 4. Проверить**

Удалите старое приложение, установите новый APK, войдите. Приложение спросит разрешение на уведомления — «Разрешить».
Затем **Мой профиль → «🔔 Включить push на этом устройстве»** — должно ответить «Push включён на этом устройстве».

Push для iPhone (нужен Mac и аккаунт Apple Developer) — [mobile.md](mobile.md), раздел «Push-уведомления».

## 7. Логи и резервные копии в Telegram

Бот пишет в ваш закрытый канал, если сайт упал, появились ошибки или кто-то подбирает пароли; каждое утро
в 09:00 присылает сводку за сутки, а каждую ночь в 03:30 — копию базы в зашифрованном архиве.
Это копия на случай, если пропадёт сам сервер.

Запросы сканеров уязвимостей (ошибка `Server Reference ID did not match the expected format. Received "x"`)
в тревоги не попадают: это боты проверяют сайт на старую уязвимость Next.js, приложение их отклоняет.
В утренней сводке они видны отдельной строкой «отклонено запросов от сканеров».

**Шаг 1. Создать бота** (в Telegram)

1. Найдите **@BotFather** (с синей галочкой) → «Запустить» → отправьте `/newbot`.
2. Имя бота — любое, например `B2B Логи`. Логин — латиницей и на `bot`, например `b2b_orders_logs_bot`.
3. BotFather пришлёт **токен** вида `123456789:AAH…`. Это пароль от бота — никому не пересылайте.

**Шаг 2. Создать канал**

1. Telegram → «Создать канал» → название любое → тип **частный**.
2. Канал → название → «Администраторы» → «Добавить администратора» → найдите бота по логину → «Сохранить».
3. Напишите в канал любое сообщение, например `тест`.

**Шаг 3. Подключить на сервере**

```bash
sudo b2b-telegram setup
```

1. Вставьте токен (правой кнопкой мыши; символы не видны) → Enter.
2. Скрипт попросит написать сообщение в канал — вы уже сделали это в шаге 2, просто нажмите Enter.
3. Скрипт сам найдёт канал и пришлёт в него проверочное сообщение. Если канал не нашёлся, он попросит ввести id
   канала: перешлите любое сообщение из канала боту **@userinfobot** — он покажет id вида `-1001234567890`.

В конце скрипт покажет **пароль архивов**. **Обязательно сохраните его у себя** (менеджер паролей, бумага в сейфе).
В Telegram он не отправляется: без пароля архивы из канала не открыть, и если пропадёт сервер — пропадёт и пароль.
Показать ещё раз: `sudo b2b-telegram password`.

Отправить первую копию в канал прямо сейчас: `sudo b2b-backup`.

| Команда | Что делает |
|---|---|
| `sudo b2b-telegram test` | проверочное сообщение в канал |
| `sudo b2b-telegram status` | что подключено |
| `sudo b2b-telegram off` | выключить (включить снова — `setup`) |

В канал уходит только база: в ней все заказы, оплаты, долги, чеки и отчёты. Фото товаров остаются в копиях
на сервере. Отправлять и фото: в файле `/etc/b2b-orders/telegram.env` поставить `TELEGRAM_SEND_PHOTOS="1"`.

## 7а. Вход по коду из Telegram (и SMS)

На странице входа появляются «Войти по коду из Telegram» и «Забыли пароль?». Человек вводит номер,
нажимает «Открыть бота в Telegram» → «Старт» и получает 6-значный код. В самый первый раз бот
просит ещё нажать «Поделиться номером»: так Telegram подтверждает, что номер принадлежит именно этому
человеку (без этого шага по чужому номеру можно было бы войти в чужой аккаунт). Дальше код приходит
сразу. Подключить бота можно и заранее: «Профиль» → «Telegram для кодов входа».

Это **отдельный** бот, не тот, что шлёт логи (его токен в `/etc/b2b-orders/telegram.env`).

1. В Telegram откройте @BotFather → `/newbot`, задайте имя (например, «OptoLink — вход») и
   username (например, `optom_kirish_bot`). Скопируйте токен.
2. На сервере:
   ```
   cd /opt/b2b-orders
   sudo -u b2b npm run telegram:login -- <токен>
   sudo systemctl restart b2b-orders
   ```
   Команда проверит токен, запишет его в `.env`, подключит вебхук `https://<домен>/api/telegram/webhook`
   (с секретом) и задаст боту описание на русском и узбекском. После смены домена — запустить её ещё раз без токена.
3. Проверка: откройте сайт → «Войти по коду из Telegram», введите свой номер, нажмите «Открыть бота».

Защита: код живёт 5 минут и подходит один раз; на код — 5 попыток; новый код — не чаще раза в минуту и не
больше 5 в час на номер; неудачные вводы кода считаются вместе с неверными паролями (после 5 — пауза 15 минут).
Ответ формы одинаковый для зарегистрированных и чужих номеров. После входа по коду 15 минут можно задать
новый пароль без старого.

**SMS (по желанию).** Нужен договор с Eskiz (eskiz.uz): в `.env` впишите `ESKIZ_EMAIL`, `ESKIZ_PASSWORD`,
при своём имени отправителя — `ESKIZ_FROM`, и `SMS_TEMPLATE` — текст, одобренный Eskiz, с `{code}` на месте
кода. После перезапуска на странице входа появится выбор «Telegram / SMS».

**Telegram Gateway (по желанию, платно).** Если задать `TELEGRAM_GATEWAY_TOKEN` (gateway.telegram.org),
код приходит от официального аккаунта Telegram «Verification Codes» без бота, около $0.01 за код.

## 7б. Почта техподдержки

Письма, пришедшие на ящик поддержки (например, support@optolink.uz), появляются у суперадмина
в разделе **Поддержка** (`/admin/support`) и приходят уведомлением: колокольчик, push в браузере и в приложении.
Сервер проверяет ящик по IMAP раз в минуту. Ящик открывается только для чтения: письма не удаляются
и не помечаются прочитанными, с почтой можно работать как обычно. Ответ пишется из своей почты:
кнопка «Ответить письмом» открывает почтовую программу с адресом и темой «Re: …».

1. Включите в настройках ящика доступ по IMAP и создайте **пароль приложения**:
   - Яндекс 360 / Яндекс Почта: id.yandex.ru → Безопасность → Пароли приложений → «Почта»;
     в Почте: Настройки → Почтовые программы → «С сервера imap.yandex.ru по протоколу IMAP».
   - Gmail / Google Workspace: myaccount.google.com → Безопасность → двухэтапная аутентификация → Пароли приложений.
   - Mail.ru: Настройки → Безопасность → Пароли для внешних приложений.
2. На сервере:
   ```bash
   sudo b2b-support-mail setup
   ```
   Команда спросит адрес ящика (IMAP-сервер подберёт сама по домену), пароль приложения, проверит вход
   и перезапустит сайт. Пароль хранится в `/opt/b2b-orders/secrets/support-mail.pass` (доступ только у сайта), не в `.env`.
3. Через минуту в «Поддержке» появятся письма за последние 7 дней (одним уведомлением «Почта поддержки подключена»),
   дальше — уведомление на каждое новое письмо.

Другие команды: `sudo b2b-support-mail test` (проверить вход), `status`, `off` (отключить; полученные письма остаются).

**Если хостинг закрывает исходящий порт 993** (команда `setup` пишет «Connection timed out»), письма можно
пересылать из самого Gmail скриптом Google, тогда сервер в почту не ходит:
1. На сервере: `sudo b2b-support-mail gmail-script`. Команда создаст секрет, перезапустит сайт и выведет текст скрипта
   с уже вписанным адресом сайта и секретом.
2. Войдите в Gmail поддержки, откройте script.google.com → «Новый проект», вставьте текст, сохраните.
3. Выберите функцию `setup` → «Выполнить», разрешите доступ («Дополнительно» → «Перейти в проект»).
   Скрипт будет раз в минуту отправлять новые письма на `/api/support-mail/inbound`. Сменить секрет:
   `sudo b2b-support-mail gmail-script --new` и вставить новый текст скрипта.
Ошибка входа видна и на странице «Поддержка».

## 8. Обновление

Когда в GitHub (ветка `main`) появились изменения, на сервере:

```bash
sudo b2b-update
```

Скрипт сам делает резервную копию, скачивает новый код, обновляет базу, собирает и перезапускает сайт.
Сборка идёт 2–5 минут, в это время сайт может отвечать с ошибкой — обновляйте вечером.
Если ошибка в конце — запустите ещё раз и посмотрите, на каком шаге она появляется.

## 9. Резервные копии и восстановление

Копии делаются сами каждую ночь в 03:30 и хранятся на сервере 14 дней в `/var/backups/b2b-orders`:
база `db_ДАТА.dump` и фото `uploads_ДАТА.tar.gz`. Сделать копию сейчас: `sudo b2b-backup`.

Без Telegram (раздел 7) копии лежат только на том же сервере. Тогда раз в неделю скачивайте их к себе (на компьютере):

```powershell
mkdir D:\Backups\b2b -Force
scp "root@1.2.3.4:/var/backups/b2b-orders/*" D:\Backups\b2b\
```

**Восстановить из копии на сервере** (вся база заменится на состояние из копии). Посмотреть, какие есть копии:
`sudo ls /var/backups/b2b-orders`. Затем, подставив дату:

```bash
sudo systemctl stop b2b-orders
sudo -u postgres pg_restore --clean --if-exists -d b2b < /var/backups/b2b-orders/db_ДАТА.dump
sudo tar -xzf /var/backups/b2b-orders/uploads_ДАТА.tar.gz -C /var/lib/b2b-orders
sudo chown -R b2b:b2b /var/lib/b2b-orders/uploads
sudo systemctl start b2b-orders
```

Строки с `tar` и `chown` — для фото; если восстанавливаете только базу, пропустите их.

**Восстановить из Telegram** (например, на новом сервере):

1. Установите платформу на новый сервер (разделы 1–3).
2. Скачайте из канала все части нужной копии: `b2b-db_ДАТА.7z.001` (и `.002`, … если есть) в одну папку.
3. Откройте `.7z.001` программой [7-Zip](https://www.7-zip.org/) и введите пароль архивов. Внутри — `db_ДАТА.dump`.
4. Загрузите файл на сервер (на компьютере):
   ```powershell
   scp D:\Backups\b2b\db_ДАТА.dump root@1.2.3.4:/var/backups/b2b-orders/
   ```
5. На сервере выполните первые три команды восстановления выше (`stop`, `pg_restore`, `start`).

## 10. Свой домен

1. Купите домен (например, на cctld.uz или ahost.uz). В DNS-записях домена:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | IP сервера |
   | A (или CNAME на сам домен) | `www` | IP сервера |

   Другие записи A и AAAA для `@` и `www` (заглушка регистратора) удалите, иначе сертификат не выдадут.
2. Дождитесь, пока домен станет активным и записи заработают (от нескольких минут до пары часов).
   Проверка на компьютере: `nslookup optolink.uz` показывает IP сервера.
3. На сервере:
   ```bash
   sudo b2b-set-domain optolink.uz
   ```
   Команда сама проверит DNS, выпустит сертификат HTTPS (и для `www`, который переадресует на основной адрес),
   а прежний адрес (например, `1-2-3-4.sslip.io`) будет переадресовывать на новый. Бот входа в Telegram
   переключится на новый адрес. Если сертификат не выдан, всё возвращается как было и сайт работает по старому адресу.
4. В GitHub поменяйте переменную `MOBILE_SERVER_URL` на `https://optolink.uz`, пересоберите APK (раздел 5)
   и раздайте его пользователям: старое приложение на новый адрес не перейдёт.
5. Войти на новом адресе нужно заново: вход привязан к адресу сайта.

## 11. Если что-то не работает

| Задача | Команда на сервере |
|---|---|
| Работает ли сайт | `sudo systemctl status b2b-orders` |
| Последние ошибки сайта | `sudo journalctl -u b2b-orders -n 50` |
| Журнал в реальном времени (выход — Ctrl+C) | `sudo journalctl -u b2b-orders -f` |
| Перезапустить сайт | `sudo systemctl restart b2b-orders` |
| Изменить настройки | `sudo nano /opt/b2b-orders/.env` (сохранить — Ctrl+O, Enter, выйти — Ctrl+X), затем перезапуск |
| Срок HTTPS-сертификата | `sudo certbot certificates` |
| Место на диске | `df -h /` |

**Установка зависла в самом начале или `apt-get update` выдаёт ошибки.** У сервера закрыт исходящий интернет. Проверка:
`curl -4 -sS -m 10 -o /dev/null -w "%{http_code}\n" https://archive.ubuntu.com` должна вывести число (200 или 301), а не ошибку.
Попросите поддержку хостинга открыть исходящие соединения (порты 80, 443, 53).

**Сайт не открывается по адресу.** Проверьте, что в панели хостинга открыты входящие порты 80 и 443.
Если служба не работает (`systemctl status` показывает `failed`), причина — в `journalctl -u b2b-orders -n 50`.

**«Сертификат не получен» в конце установки.** Домен ещё не указывает на сервер или в панели хостинга закрыт порт 80.
Исправьте и повторите: `sudo certbot --nginx -d ДОМЕН --redirect --hsts`.

**В Telegram ничего не приходит.** `sudo b2b-telegram test` покажет ошибку. Обычно бот не добавлен администратором канала.

**Приложение не ставится поверх старого.** Удалите старое приложение и установите заново (раздел 5).
