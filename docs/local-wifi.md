# Запуск на своём компьютере и проверка с телефона по Wi‑Fi

Компьютер запускает платформу (сервер + база), телефон в той же Wi‑Fi сети открывает её в приложении (APK) или в браузере. Интернет для работы не нужен, только общий роутер.

Время: ~30 минут в первый раз, потом запуск — две команды.

---

## 1. Что установить (один раз)

### Windows

1. **Node.js 22 LTS** — https://nodejs.org → «LTS» → установщик `.msi`, все галочки по умолчанию.
2. **Git** — https://git-scm.com/download/win, всё по умолчанию.
3. **PostgreSQL 16 или 17** — https://www.postgresql.org/download/windows/ → «Download the installer» (EDB).
   - Пароль пользователя `postgres` — придумайте и запишите.
   - Порт оставьте `5432`. Stack Builder в конце можно закрыть.

Проверка в **PowerShell** (Пуск → «PowerShell»):

```powershell
node -v      # v22.x
git --version
```

### macOS

```bash
brew install node@22 git postgresql@16
brew services start postgresql@16
```

### Linux (Ubuntu)

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs git postgresql
```

## 2. База данных

Создаём пользователя `b2b` с паролем `b2b` и базу `b2b`.

**Windows:** Пуск → «SQL Shell (psql)» → на все вопросы Enter, затем пароль `postgres` из установки. Вставьте:

```sql
CREATE USER b2b WITH PASSWORD 'b2b' CREATEDB;
CREATE DATABASE b2b OWNER b2b;
\q
```

**macOS:** `psql postgres` и те же две строки. **Linux:** `sudo -u postgres psql` и те же строки.

---

## 3. Код и настройки

```powershell
cd $HOME\Desktop
git clone https://github.com/J0ma2966/b2b-orders.git
cd b2b-orders
copy .env.example .env        # macOS/Linux: cp .env.example .env
```

Откройте `.env` в Блокноте (`notepad .env`) и проверьте строку базы:

```
DATABASE_URL="postgresql://b2b:b2b@localhost:5432/b2b?schema=public"
```

Вход по `http://` сохраняется сам, если адрес компьютера обычный для домашней сети (`192.168.…`, `10.…`, `172.16–31.…`). Если IP другой и после входа телефон снова просит войти, добавьте в `.env` строку `COOKIE_SECURE="0"` и перезапустите сервер. На настоящем сервере с HTTPS её не ставят.

## 4. Установка и данные

```powershell
npm install                     # 2–5 минут
npm run db:deploy               # таблицы
npm run db:seed                 # территории Узбекистана, комиссия, супер-админ
npx tsx scripts/local-demo.ts   # тестовый поставщик, доставщик, магазин и 12 товаров
```

Команды можно запускать повторно — ничего не задвоится.

## 5. Запуск

```powershell
npm run build                          # 1–3 минуты, после каждого обновления кода
npx next start -H 0.0.0.0 -p 3000      # сервер; окно не закрывать
```

`-H 0.0.0.0` — сервер слушает не только сам компьютер, но и Wi‑Fi сеть. Остановить — `Ctrl+C`. В следующий раз достаточно `cd Desktop\b2b-orders` и `npx next start -H 0.0.0.0 -p 3000` (и `npm run build` перед ним, если обновляли код через `git pull`).

Проверка на компьютере: http://localhost:3000

> Для телефона используйте именно `build` + `start`: режим разработки `npm run dev` по умолчанию не отдаёт служебные файлы на другие адреса сети, и страница на телефоне может не работать.

## 6. Адрес компьютера в сети

**Windows:** в PowerShell `ipconfig` → раздел «Адаптер беспроводной локальной сети Wi‑Fi» → **IPv4-адрес**, например `192.168.1.10`.
**macOS:** `ipconfig getifaddr en0`. **Linux:** `hostname -I` (первый адрес).

Адрес для телефона: **`http://192.168.1.10:3000`** (ваш IP + `:3000`).

Роутер может выдать компьютеру другой адрес после перезагрузки. Чтобы не менять его каждый раз — закрепите IP за компьютером в настройках роутера (DHCP reservation).

## 7. Брандмауэр (иначе телефон не достучится)

**Windows:**
1. Параметры → Сеть и Интернет → Wi‑Fi → ваша сеть → **Тип сетевого профиля: Частная**.
2. При первом запуске сервера Windows спросит про Node.js — отметьте **«Частные сети»** → Разрешить.
3. Если окно не появилось или нажали «Отмена» — PowerShell **от имени администратора**:
   ```powershell
   New-NetFirewallRule -DisplayName "B2B orders 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private
   ```

**macOS:** Системные настройки → Сеть → Брандмауэр — если включён, разрешить входящие для `node`.
**Linux:** `sudo ufw allow 3000/tcp` (если ufw включён).

Проверка: на телефоне в браузере открыть `http://192.168.1.10:3000` — должна открыться страница входа.

## 8. Приложение на Android (APK)

Нужен Android 8.0 или новее.

1. Скачайте `b2b-orders-wifi-test.apk` на телефон (Telegram «Избранное», кабель, Google Drive).
2. Откройте файл → Android попросит разрешить установку из этого источника → разрешить → «Установить». Play Защита может предупредить о неизвестном разработчике — «Всё равно установить» (это тестовая сборка без подписи магазина).
3. При первом запуске приложение спросит **адрес сервера** — введите `http://192.168.1.10:3000` → «Подключиться».
4. Сменить адрес: остановите сервер (или отключите Wi‑Fi) → откроется «Нет связи» → **«Сменить адрес сервера»**. Или: Настройки Android → Приложения → «Оптовые заказы» → Хранилище → Очистить данные.

Это одно приложение для всех ролей: магазин, поставщик и доставщик видят своё после входа. Вход сохраняется на 30 дней: при следующем запуске приложение сразу открывает кабинет. Выйти — «Профиль» → «⏻ Выйти» (у магазина) или «Мой профиль» → «⏻ Выйти из аккаунта» (у всех ролей).

Без APK можно проверять в **Chrome** на телефоне по тому же адресу, а меню ⋮ → «Добавить на гл. экран» даст ярлык.

### iPhone

Собрать приложение для iPhone можно только на Mac с Xcode (см. `docs/mobile.md`). Без Mac — откройте `http://192.168.1.10:3000` в Safari, «Поделиться» → «На экран „Домой“».

## 9. Учётные записи

| Роль | Телефон | Пароль |
|---|---|---|
| Супер-админ | +998 90 000 00 00 | `admin12345` (при первом входе попросит сменить) |
| Поставщик «Демо Опт», сам развозит | +998 90 100 00 01 | `demo12345` |
| Доставщик поставщика | +998 90 100 00 02 | `demo12345` |
| Магазин «Демо» (Ташкент, Юнусабад) | +998 90 100 00 03 | `demo12345` |

Сценарий: магазин кладёт товары в корзину и оформляет заказ → поставщик принимает и назначает доставщика (или берёт сам: «Ещё» → режим доставки) → доставщик «Выехал» → магазин показывает QR в заказе → доставщик принимает код → чек, долг, отчёты.

Удобно держать два устройства: телефон с приложением (магазин или доставщик) и компьютер с браузером (поставщик). Новые учётные записи можно регистрировать как обычно — поставщика подтверждает супер-админ.

## 10. Что не работает без HTTPS

Браузеры и Android разрешают некоторые функции только на защищённых (https) адресах. По `http://192.168…`:

| Функция | По Wi‑Fi (http) | Как проверить |
|---|---|---|
| Камера для QR | в приложении (новый APK) — да, приложение само спросит разрешение на камеру; в браузере телефона — нет | В браузере ввести код вручную — он написан под QR у магазина. Или вариант с HTTPS ниже |
| Фото с камеры (брак, проблема с доставкой, фото магазина) | да: кнопка «📷 Снять фото», приложение спросит разрешение на камеру; «🖼 Из галереи» — готовые снимки | — |
| «📍 Моё местоположение» | в приложении (APK от 7 ноября и новее) — да, приложение само спросит разрешение; в браузере телефона — нет | В браузере точку можно поставить на карте вручную |
| Офлайн доставщика, Web Push, установка PWA | нет | Вариант с HTTPS |
| Системные push в приложении | нет | Нужен проект Firebase (`docs/mobile.md`); колокольчик уведомлений работает всегда |
| Всё остальное: заказы, остатки, доставка, оплата, долги, отчёты, печать чека | да | — |

### Вариант с HTTPS: всё, включая камеру

Бесплатный туннель Cloudflare даёт временный https-адрес для вашего компьютера (нужен интернет):

1. Скачайте `cloudflared` — https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/ (Windows: `winget install --id Cloudflare.cloudflared`).
2. При работающем сервере во втором окне: `cloudflared tunnel --url http://localhost:3000`
3. Он напечатает адрес вида `https://xxxx.trycloudflare.com` — введите его в приложении («Сменить адрес сервера») или откройте в браузере телефона. Wi‑Fi при этом может быть любой.

Адрес меняется при каждом запуске туннеля. Не держите туннель открытым дольше проверки: по ссылке платформу видит любой, у кого она есть.

## 11. Если не работает

| Что видно | Что сделать |
|---|---|
| На телефоне «Нет связи» / страница не открывается | Телефон в той же Wi‑Fi (не гостевой, не мобильный интернет)? IP верный (`ipconfig`)? Сервер запущен с `-H 0.0.0.0`? Правило брандмауэра (п. 7)? Некоторые роутеры изолируют устройства (AP/client isolation) — выключить в роутере или раздать Wi‑Fi с телефона на ноутбук |
| После входа или при переходе на другую вкладку снова страница входа | Код старше 7 ноября 2026 → `git pull`, `npm run build`, перезапуск. Если не помогло (IP не `192.168…`/`10…`/`172.16–31…`) — `COOKIE_SECURE="0"` в `.env` и перезапуск |
| `npm run db:deploy`: `P1001 Can't reach database` | Служба PostgreSQL не запущена (Windows: Службы → postgresql-x64-… → Запустить) или неверный `DATABASE_URL` |
| `password authentication failed for user "b2b"` | Пользователь не создан — повторить п. 2 |
| `Error: listen EADDRINUSE :3000` | Порт занят — закрыть прежний сервер или запустить с `-p 3001` (и в телефоне `:3001`) |
| Установка APK: «Приложение не установлено» | Удалить прежнюю версию «Оптовые заказы» и поставить заново |

## 12. Логи для разбора ошибок

**Сервер.** Всё, что пишет сервер, видно в окне, где запущен `npx next start …`. Ошибки начинаются с `⨯ Error`. Чтобы сохранить лог в файл (PowerShell):

```powershell
npx next start -H 0.0.0.0 -p 3000 2>&1 | Tee-Object -FilePath server.log
```

macOS/Linux: `npx next start -H 0.0.0.0 -p 3000 2>&1 | tee server.log`. Файл `server.log` появится в папке проекта.

**Приложение на телефоне (консоль, сеть, cookie).** Тестовый APK разрешает отладку WebView:

1. На телефоне: Настройки → О телефоне → 7 раз нажать «Номер сборки» → появится «Для разработчиков» → включить **Отладка по USB**.
2. Подключить телефон кабелем к компьютеру, на телефоне разрешить отладку для этого компьютера.
3. На компьютере открыть Chrome → в адресной строке `chrome://inspect/#devices` → под телефоном появится «Оптовые заказы» / WebView → **inspect**.
4. Откроются инструменты разработчика для страницы в приложении: вкладка **Console** — ошибки JavaScript, **Network** — запросы (у запроса входа во вкладке Cookies видно, принята ли cookie `b2b_session`), **Application → Cookies** — сохранённые cookie.

Ошибки из Console можно скопировать (правый клик → Save as…) и прислать вместе с `server.log`.

**Android целиком** (если приложение закрывается): `adb logcat *:E` из Android SDK Platform Tools.
