# Публикация Android-приложения в Google Play

Сборка для Play делается в GitHub Actions (**Actions → Android release → Run workflow**): получается подписанный **AAB** (его загружают в Play Console) и подписанный **APK** того же выпуска (поставить на свой телефон и проверить). Отладочные APK из сборки **Mobile** в Play загрузить нельзя.

Требования Google Play сверены 9 ноября 2026 г.

## Что уже выполнено в приложении

| Требование Play | Как выполнено |
|---|---|
| Target API: с 31.08.2025 — не ниже 35 для новых приложений и обновлений; с 31.08.2026 — 36 | `targetSdkVersion 36`, `compileSdk 36`, `minSdk 26` (Android 8.0). Сборка проверяет targetSdk 36 и падает, если иначе |
| Формат Android App Bundle, Play App Signing | `bundleRelease`, подпись ключом загрузки; ключ распространения хранит Google |
| Страницы памяти 16 КБ (Android 15+) | Своих нативных `.so` в приложении нет |
| Не отладочная сборка | `debuggable false`, отладка WebView выключена, ввод адреса сервера на телефоне (`DevServerPlugin`) работает только в отладочной сборке. Сборка проверяет это |
| Политика конфиденциальности | `https://<домен>/privacy` (ru, uz), ссылки на входе, регистрации и в профиле |
| Удаление аккаунта в приложении и по ссылке | Профиль → «Удалить аккаунт»; открытая страница `https://<домен>/account-deletion` |
| Разрешения только по месту использования | Камера (QR, фото брака), геолокация «при использовании» (точка магазина), уведомления (Android 13+), интернет, вибрация. Фоновой геолокации и доступа ко всем фото нет — отдельные декларации не нужны |
| Только HTTPS | `network_security_config` запрещает HTTP в рабочей сборке |
| Нет встроенных покупок | Платформа не проводит платежи — Google Play Billing не нужен |
| Не «просто сайт в обёртке» (политика спама / минимальной функциональности) | Сайт свой, плюс нативные функции: push, сканер QR, печать, «Поделиться», офлайн доставщика, экран «Нет связи» |

## Шаг 0. До первой загрузки

1. **Свой домен.** Адрес сервера зашивается в приложение при сборке. Сейчас это `https://89-125-62-98.sslip.io` — работает, но привязан к IP сервера: при переезде на другой сервер старые установленные приложения перестанут открываться. Лучше купить домен (например в `.uz`), выполнить на сервере `sudo b2b-set-domain ДОМЕН` и поменять переменную репозитория `MOBILE_SERVER_URL` **до** первой публикации.
2. **Иконка.** Сейчас временная «коробка». Положите свой логотип 1024×1024 без прозрачности в `mobile/resources/icon.png` и запустите `python3 scripts/mobile-icons.py` (или попросите Claude).
3. **Реквизиты владельца в политике.** На сервере в `.env` заполнены `LEGAL_OPERATOR_NAME`, `LEGAL_CONTACT_EMAIL`, `LEGAL_CONTACT_PHONE`; откройте `/privacy` и проверьте, что там ваши данные.
4. **Push (по желанию).** Без Firebase приложение работает, только системные push не приходят. Настройка — [docs/mobile.md](mobile.md), «Firebase для Android по шагам». Секрет `GOOGLE_SERVICES_JSON` сборка подхватит сама.

## Шаг 1. Аккаунт разработчика Google Play

<https://play.google.com/console/signup> — разовый взнос **25 $**, банковская карта.

| | Личный аккаунт | Аккаунт организации |
|---|---|---|
| Что нужно | Паспорт, телефон, адрес | Юрлицо и номер **D-U-N-S** (бесплатно, через Dun & Bradstreet, 1–4 недели) |
| Перед выходом в продакшн | **Закрытое тестирование: не меньше 12 тестировщиков 14 дней подряд**, затем заявка на доступ к продакшну (ответ обычно до 7 дней) | Не требуется |
| Имя в магазине | Ваше имя | Название компании |

Для B2B-платформы удобнее аккаунт организации. Google проверяет личность/организацию (Android developer verification) — пока проверка не пройдена, публиковать нельзя.

## Шаг 2. Ключ загрузки (один раз)

На своём компьютере, в PowerShell, в папке `D:\Projects\b2b-orders`:

```powershell
git pull
powershell -ExecutionPolicy Bypass -File scripts\android-upload-key.ps1
```

Скрипт спросит пароль (вводится скрыто) и название владельца, создаст `upload.jks` в папке `b2b-orders-upload-key` вашего профиля пользователя и скопирует файл в буфер обмена в виде текста. Если скрипт пишет, что нет `keytool`, установите Java: `winget install EclipseAdoptium.Temurin.21.JDK` и откройте новое окно PowerShell.

Затем GitHub → репозиторий **b2b-orders → Settings → Secrets and variables → Actions → New repository secret**:

| Имя секрета | Значение |
|---|---|
| `ANDROID_UPLOAD_KEYSTORE` | Ctrl+V (то, что скопировал скрипт) |
| `ANDROID_UPLOAD_KEYSTORE_PASSWORD` | пароль, который вы ввели |

Сохраните копию папки `b2b-orders-upload-key` и пароль в надёжном месте (флешка, менеджер паролей). Пароль и файл никому не пересылайте, в том числе в чат. Если ключ потеряется — Play App Signing позволяет заменить ключ загрузки через поддержку Google, но это занимает дни.

## Шаг 3. Сборка

**Actions → Android release → Run workflow**:
- `versionName` — версия для пользователей: `1.0.0`, потом `1.0.1`, `1.1.0`…
- `versionCode` — оставить пустым (номер берётся сам и растёт с каждым запуском).

Через ~10 минут внизу страницы запуска, в **Artifacts**, появится `android-release-<версия>-<номер>` (zip): внутри `.aab` для Play и `.apk` для проверки. Перед загрузкой поставьте APK на телефон (старое приложение с этим же именем сначала удалите — у отладочных сборок другая подпись) и пройдите вход, заказ, QR-приёмку.

В журнале шага «Ключ подписи» печатается отпечаток SHA-256 ключа загрузки, в шаге «Проверка сборки» — пакет, версия, targetSdk и список разрешений.

## Шаг 4. Play Console

1. **Создать приложение**: название «Оптовые заказы» (до 30 символов), язык по умолчанию — русский, «Приложение», «Бесплатное».
2. **Тестирование → Закрытое тестирование → Создать выпуск** → загрузить `.aab`. На предложение Play App Signing ответить «Использовать» (ключ распространения создаст Google). Добавить тестировщиков списком e-mail (Google-аккаунты) или через Google Group; им отправить ссылку «Принять приглашение». Для личного аккаунта — 12+ человек, которые остаются в тесте 14 дней подряд.
3. **Политика → Содержание приложения** (все пункты обязательны):

| Пункт | Что ответить |
|---|---|
| Политика конфиденциальности | `https://<домен>/privacy` |
| Доступ к приложению | «Часть функций доступна только после входа» → логины и пароли тестовых аккаунтов: магазин, поставщик (с «Сам развожу заказы»), доставщик. Создайте их на рабочем сервере у отдельного тестового поставщика; входа по SMS нет — только телефон + пароль |
| Реклама | Нет |
| Возрастной рейтинг (анкета IARC) | Категория «Утилиты, продуктивность, связь…»; насилия, азартных игр и т. п. нет; пользователи общаются? — нет; покупки цифровых товаров — нет |
| Целевая аудитория | 18+ (взрослые, приложение для бизнеса), не для детей |
| Безопасность данных (Data safety) | См. таблицу ниже |
| Удаление аккаунта | Ссылка `https://<домен>/account-deletion`; удаляются имя, телефон, пароль, сессии; заказы и учётные документы хранятся у организаций |
| Финансовые функции | «Не предоставляет финансовых функций» (платформа учитывает долги между организациями, но не выдаёт кредиты и не проводит платежи) |
| Госприложение, здоровье, новости, VPN, COVID | Нет |

**Data safety**: собирает ли приложение данные — да; передаются ли третьим лицам — нет; шифрование при передаче — да; можно запросить удаление — да.

| Тип данных | Собирается | Зачем | Обязательно |
|---|---|---|---|
| Личные данные: имя, номер телефона, адрес (магазина) | да | Работа приложения, управление аккаунтом | да |
| Местоположение: приблизительное и точное | да | Работа приложения (точка магазина на карте) | нет |
| Фото и видео | да | Работа приложения (фото брака в заявке на замену) | нет |
| Финансовая информация: история покупок, другое (долги, оплаты) | да | Работа приложения | да |
| Идентификаторы устройства (токен push) | да, если включён push | Работа приложения | нет |

4. **Основная страница в магазине**: краткое описание (до 80 символов), полное (до 4000), иконка 512×512 PNG, графика 1024×500, минимум 2 скриншота телефона. Перевод на узбекский — «Переводы → Добавить свой перевод → uz». Категория — «Бизнес», контактный e-mail.
5. **Страны**: Узбекистан (и другие по желанию).
6. Для личного аккаунта: через 14 дней теста — **Панель → Подать заявку на доступ к продакшну** (ответить на вопросы о тестировании). Потом **Рабочая версия → Создать выпуск** с тем же или новым AAB → отправить на проверку (обычно от нескольких часов до 7 дней).

## Обновления

Изменения сайта (страницы, логика) приходят в приложение сами — новый выпуск не нужен. Новый AAB нужен только при изменении нативной части (`mobile/android`, плагины Capacitor, иконка, адрес сервера): **Run workflow** с новой `versionName` → загрузить AAB в Play. Ежегодно проверяйте требование target API (обычно новое — к 31 августа).
