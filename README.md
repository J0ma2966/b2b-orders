# Оптовые заказы — B2B-платформа поставщиков и магазинов

Реализация ТЗ v2.1. Поставщики ведут каталог, остатки и доставку, магазины заказывают у поставщиков своей территории, платформа учитывает приёмку, оплаты, долги и комиссию (деньги не проводит).

## Стек

- Next.js 16 (App Router, Server Actions, Cache Components), React 19, TypeScript
- PostgreSQL + Prisma 7
- Tailwind CSS 4, Leaflet + OpenStreetMap
- PWA: магазин и доставщик ставят приложение на телефон
- Vitest (логика), Playwright (сквозной сценарий)

## Запуск

```bash
cp .env.example .env          # указать DATABASE_URL
npm install
npm run db:deploy             # миграции
npm run db:seed               # территории Узбекистана, комиссия 3%, супер-админ
npm run dev
```

Супер-админ по умолчанию: `+998900000000` / `admin12345`, при первом входе система попросит сменить пароль. В продакшене задайте `SUPERADMIN_PASSWORD`.

В продакшене приложение работает за обратным прокси (nginx и т. п.), который дописывает адрес клиента в конец `X-Forwarded-For` (`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`). Лимит попыток входа и журнал берут последний адрес из этого заголовка, поэтому без прокси подменить его может сам клиент.

Фоновые задачи (напоминания, автоотмена заказов без ответа, сроки долгов, счета на комиссию) запускаются внутри сервера каждые 5 минут. При нескольких экземплярах их можно оставить в одном (`JOBS_DISABLED=1` в остальных) или запускать снаружи: `curl -X POST -H "Authorization: Bearer $CRON_SECRET" https://…/api/cron`.

Проверки: `npm test` (складские тесты с базой: `TEST_DATABASE_URL=postgresql://... npm test`), `npm run typecheck`, `npm run lint`, `npm run build`.
Сквозной сценарий на запущенном приложении: `node tests/e2e/flow.mjs`.

## Структура

| Путь | Что там |
|---|---|
| `prisma/schema.prisma` | Модель данных |
| `src/lib/auth` | Сессии (cookie + таблица Session), пароли, проверка ролей, «от имени» |
| `src/lib/audit.ts` | Аудит: кто, от чьего имени, поле, старое → новое значение |
| `src/lib/territory*.ts` | Территории доставки и доступность поставщика для магазина |
| `src/lib/statuses.ts` | Статусы и допустимые переходы |
| `src/lib/stock*.ts` | Остатки: атомарные операции, журнал, правила движения |
| `src/lib/pricing.ts` | Изменение цены: история и антифрод |
| `src/app/(auth)` | Вход, регистрация магазина и поставщика |
| `src/app/admin` | Кабинет супер-админа |
| `src/app/supplier` | Кабинет поставщика (владелец и администраторы) |
| `src/app/courier` | Кабинет доставщика |
| `src/app/shop` | Кабинет магазина (мобильный) |
| `docs/decisions.md` | Решения по пробелам ТЗ |

## Этапы (ТЗ п. 88)

- [x] Этап 1 — пользователи, роли, регистрация, вход, поставщики и модерация, магазины и точки, сотрудники, доставщики, профили, территории, карта, права, аудит, уведомления
- [x] Этап 2 — категории, товары, фото, единицы и цены, остатки, резервирование, журнал склада, удаление из каталога; антифрод снижения цены
- [x] Этап 3 — корзина по поставщикам, оформление с повторной проверкой и резервом, статусы до назначения доставщика, отмена, принудительная продажа, бонусные акции
- [x] Этап 4 — выезд доставщика, проблемы доставки, запрос отмены в пути, приёмка по QR (сканер камеры или код вручную), частичная приёмка, чек и накладная (печать / PDF)
- [x] Этап 5 — оплата при приёмке, распределение (заказ → прежний долг → переплата), работа в долг и лимит, погашение долга, корректировки, история задолженности
- [x] Этап 6 — заявки на замену с фото и видео, согласование с резервом, задание доставщику или привязка к заказу, «Возвращённые товары» и возврат в оборот
- [x] Этап 7 — бонусы: акции, выдача при оформлении, расход бонусов в отчётах
- [x] Этап 8 — отчёты поставщика и платформы за период (продажи, финансы, товары, логистика, замены), комиссии, карты
- [x] Этап 9 — контроль: антифрод, корректирующие операции, журнал действий поставщика, аудит, push-уведомления

## Проверка

```bash
TEST_DATABASE_URL=postgresql://…/b2b_test npx vitest run   # модульные и интеграционные тесты
npm run build && npm start                                  # затем на свежей БД:
ADMIN_PW=admin12345 CHROMIUM_PATH=/opt/pw-browsers/chromium node tests/e2e/flow.mjs
```

Перевод: `node scripts/i18n-check.mjs --missing` — строки без узбекского перевода; `DATABASE_URL=… node tests/e2e/uz-scan.mjs` после сквозного сценария обходит все страницы на узбекском и печатает оставшуюся кириллицу.

Сквозной сценарий проходит этапы 1–6 в браузере: регистрация и модерация, каталог, заказ, доставка с QR, частичная приёмка в долг, погашение, замена и возврат в оборот, отчёты.
